## Почему именно так

**Участник 1** настраивает инфраструктуру и БД первым — это разблокирует остальных. Feature 5 идёт к нему же, потому что завязана на ту же БД.

**Участник 2** берёт Feature 3 — она независима и можно стартовать сразу. Feature 1 идёт следом, когда auth-контекст от Участника 1 уже готов.

**Участник 3** берёт Feature 4 — она зависит от Feature 3, поэтому разные люди могут работать параллельно на моках. Feature 7 идёт к нему же, так как i18n затрагивает весь UI.

Feature 3 и Feature 4 намеренно у разных людей — обе по 120 баллов, одна зависит от другой, параллельная работа на моках экономит время.

## Риски и открытые вопросы

### Никто не назначен ответственным

| Задача | Риск |
|---|---|
| Тестирование | ❓ Открытый вопрос — кто берёт и когда. Потенциально **-250 баллов** если нет тестов вообще |
| CORS-proxy (API route в Next.js) | Архитектурно нетривиально, блокирует Try-It-Out у Участника 3 |
| i18n переводы | Затрагивают все фичи всех троих, ответственен только Участник 3 |

### Пропущенные зависимости

- **Схема БД `RequestRecord`** должна быть согласована всеми до начала Feature 4 — иначе Try-It-Out будет сохранять не те поля, и Feature 5 не сможет их отобразить
- **CORS-proxy** блокирует Try-It-Out у Участника 3 — Участник 1 должен отдать API route заранее
- **i18n** затрагивает тексты во всех фичах — Участник 3 не может завершить переводы пока остальные не закончат свои UI
